# Capture 784 Export Debug Report

Date: 2026-05-24

## Implementation

Added optional UART dump support in the 800x600@40 branch:

- `src/uart_tx.v`
- `src/capture_dump_controller.v`
- `camera_live_top.v` wiring under `DEBUG_DUMP_ENABLE`

After `capture_done`, the controller reads MNIST RAM addresses `0..783` in the I_clk domain and emits a text dump. A new capture is blocked while the dump is busy.

## Output Format

```text
BEGIN_CAPTURE
threshold=100
roi=448
block=16
addr,value
0,0x00
1,0x12
...
783,0x00
END_CAPTURE
```

Values are the exact 8-bit MNIST pixels generated by `streaming_mnist_capture`, read from the dual-clock MNIST RAM.

## Board Interface

For this no-NN branch:

- `FLASH_CS_N` is held high so the external flash ignores traffic.
- `FLASH_MOSI` is used as debug UART TX.
- `FLASH_SCLK` indicates dump busy.
- UART settings: `115200 8N1`, I_clk assumed 27 MHz.

This is a practical debug hook, but it may require probing the flash MOSI net or remapping to a more convenient header pin later.

## Decision

Keep the debug dump path for board capture/export work. It costs LUTs and routing, but it does not add BSRAM/DSP and it creates the required hardware-vs-Python checkpoint before NN integration.
